# 可更新页跨版本更新日志

目标：可更新卡片列出当前来源版本之后、目标版本以内的全部来源记录，从新到旧排列，沿用现有 `Divider()`。每条记录标明版本、软件源和发布时间，日志完整显示；空日志显示“未提供更新说明”，缺少发布时间显示“发布时间未知”。日期按设备区域显示日期和时间。

采用更新检查时生成不可变日志快照的方案，避免视图再次请求软件源或混入其他订阅的日志。筛选基线使用签名包保存的来源版本，不能用可能与来源不同的 IPA 内版本。保留现有最新版本 `whatsNew`，供详情页使用。旧格式软件源只有单版本时仍生成一条记录；不推测来源未提供的历史。

实施与验收：

- [x] 在现有 UpdateManager 模拟器回归中增加乱序历史、语义版本排序、边界、来源版本基线、缺失日志/日期及旧格式案例，先确认失败。
- [x] 为更新候选保存版本日志、发布时间快照，在可更新卡片循环展示，每条使用现有分隔线。
- [x] 执行更新管理器回归与完整模拟器构建，验收浅色、深色和大字号的生产组件。
- [ ] 同步应用页文档，执行发布合同检查、提交 push 并核对远端 SHA，登记 ready，等待协调器 GitHub Release 与固定 OTA 凭证。

独立审查补充：软件源页面只持有包的来源信息，其临时候选曾覆盖完整日志快照。`selectCandidate` 现在按本地 UUID、本地版本及来源版本身份复用已检查候选；真实入口回归先失败后通过。冻结后的修复使用后续批次，不能修改已冻结提交。
