# SignOs 中文更新日志发布契约

用户已确认：具体中文日志是发布必填项，缺失时阻止发布；GitHub 与 OTA 使用同一份变更内容，现有软件源从正式 Release 同步。

任务 ready 验证 JSON 携带 releaseNotes，结构为 language: zh-Hans 和 changes: 非空中文条目数组。每个参与任务填写实际新增、改进或修复内容；适配器在版本分配、构建及发包前检查，拒绝缺失、纯英文、格式错误、常见笼统占位说明，不自动补写替代内容。相同说明去重，多任务变更按参与任务顺序汇总。

协调器 0.1.4 的公开清单只保留固定字段。SignOs prepare 生成 .release-notes.json，包含批次 ID、已分配版本/构建号与各任务的 ID、SHA 和公开中文说明，由正常 freeze 一并提交；不复制私有配置或验证记录。CI 校验它与冻结清单的身份一致，元数据记录 SHA-256，CI 产物保留相同文件，标签流程再次验证。通用协调器及其协议保持现有行为。

同一渲染函数生成带版本/构建号的中文变更日志。GitHub Release 正文追加中文安装与校验说明；OTA notes 使用同一段日志，软件源继续读取 Release。验收核对实际正文及 OTA JSON 与冻结内容，即使 IPA 校验已缓存，日志错误仍失败；暂存包恢复在固定入口切换前校验日志。

日志校验是格式及已知占位检查：条目至少四个汉字、language 为 zh-Hans，拒绝 TODO/TBD 等占位；事实准确性通过任务复核确保。新规则不改写历史已发布批次和标签。新任务及关联修复任务均应按当前规则提供完整中文说明，缺失时停止，不隐式从旧日志推断。

验证：缺失/占位日志先失败再通过；多任务汇总与去重；任务/版本/批次及产物散列绑定；实际 GitHub/OTA 错误日志在缓存命中时仍被拒绝；正确缓存无需重签或重发；错误暂存日志不能激活。既有包校验、有限重试、标签不可移动等回归继续运行。改动涉及发布构建输入，由协调器完成新批次本地 Release、main CI、GitHub Release、OTA 与软件源日志回验。
